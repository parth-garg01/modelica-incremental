# Gap classification: Cauer filter's 2 unmatched equations

Requested before Feature 5 could treat the Cauer filter as a flagship: classify
the 2/69 unmatched equations in `results/fixtures/CauerLowPassAnalog.json` as
one of (a) needs index reduction, (b) safely droppable redundant/alias
equations, or (c) a bug in `src/matching.py`. **Classification: (a), index
reduction.** Confirmed by circuit topology, not just equation shape.

## The two equations

```
eq 62: connect(C2.n, C3.p)  ->  C2.n.v = C3.p.v
eq 66: connect(C4.n, C5.p)  ->  C4.n.v = C5.p.v
```

Both are ordinary potential-equality equations generated by `connect()`
statements between two capacitor pins -- nothing unusual about their shape.
`src/matching.py`'s Kuhn's-algorithm matcher is independently verified correct
(finds a provably-complete matching on every smaller subgraph pulled from this
same model; see the module's own docstring and `tests/test_matching.py`), so
this is not (c), a matcher bug.

## Circuit topology (from `msl_src/Modelica/Electrical/Analog/Examples/CauerLowPassAnalog.mo`)

Electrical nodes, as merged by every `connect()` statement in the model:

| Node | Pins merged into it |
|---|---|
| A | R1.n, C1.p, L1.p, C2.p |
| B | L1.n, C2.n, C3.p, C4.p, L2.p |
| C | L2.n, C4.n, C5.p, R2.p |
| D | C1.n, G.p, C3.n, C5.n, R2.n, V.n |
| E | R1.p, V.p |

Two-terminal components, as edges between those nodes:

| Component | Connects |
|---|---|
| R1 | E -- A |
| C1 | A -- D |
| L1 | A -- B |
| C2 | A -- B |
| C3 | B -- D |
| C4 | B -- C |
| L2 | B -- C |
| C5 | C -- D |
| R2 | C -- D |
| V  | E -- D |

**Two loops made entirely of capacitors, with no resistor or independent
source breaking either one:**

- **C1 - C2 - C3**: A --C1-- D --C3(reversed)-- B --C2(reversed)-- A
- **C3 - C4 - C5**: B --C3-- D --C5(reversed)-- C --C4(reversed)-- B

This is the standard "capacitor-only loop" (equivalently, "capacitor cutset"
viewed from the dual side) pattern that produces a structural KVL redundancy:
around a loop of pure capacitors, Kirchhoff's voltage law forces a linear
relationship among the loop's capacitor voltages that their individual
`der(v) = i/C` dynamics do not, on their own, respect -- the system is not
consistently integrable without differentiating one of the loop's equations
(classic DAE index 2, requiring index reduction, e.g. Pantelides' algorithm
plus dummy-derivative selection, before causalization can proceed). Each
independent capacitor-only loop contributes exactly one such redundant
constraint. Two independent loops (sharing C3) -> exactly two unresolvable
equations under a matcher that does no differentiation, which is exactly what
was observed (`unmatched_equations = [62, 66]`, deterministic and confirmed
stable across hash seeds).

## Consequence for Stage A

Rumoca clearly performs index reduction internally (it compiles and simulates
this model correctly); this project's matcher does not attempt to replicate
that. Implementing general index reduction (structural analysis to find the
minimal differentiation set, consistent dummy-derivative selection, and
downstream codegen that handles the differentiated equations) is a
compiler-backend-scale undertaking on its own, disproportionate to the rest of
this project's remaining scope.

**Decision: the Cauer filter is not used as Feature 5's bit-identical
flagship.** Stage A's generality claim narrows to **index-1 implicit-equation
models** -- real Modelica components wired via `connect()`, producing genuine
anonymous KCL/KVL residual equations (the actual generality gap Feature 1 was
built to close), but without a topology whose reactive elements form a
resistor-free loop or cutset. Feature 5 uses a small real-MSL-component
circuit (Resistor + Capacitor + Ground + voltage Source, in series -- no
capacitor-only loop is even topologically possible with a single capacitor)
instead. The Cauer filter and this finding remain documented as an honest,
precisely-characterized limitation, per the standing discipline (prd-combined.md
Section 3, rule 6) rather than dropped silently.
